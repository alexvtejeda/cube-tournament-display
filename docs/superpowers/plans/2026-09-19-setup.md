# SETUP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build screen 9, SETUP — the operator's first screen: connect the mat, prove it, and choose
between resuming the saved event and starting a new one.

**Architecture:** One pure module (`js/core/setup-gate.js`) turns a diagnosis, a mat test and the
saved event into "which buttons are live and why". One view (`js/ui/setup.js`) draws that, reusing
SIGNAL CHECK's chain, verdict and picker rather than re-implementing them. The operator window opens
on SETUP and leaves it exactly once.

**Tech Stack:** Plain ES modules, no build step. `node --test` for the core, Puppeteer for the
browser smoke. Node 24.2+.

---

## Scope

Roadmap Phase 2, the SETUP half of "operator screens". It covers **operator spec §4** in full.

**It runs after two plans, and cannot start before both are done:**

1. **`2026-09-18-tournament-engine.md`** — the store, the event model, the drivers, the keymap, the
   Web Lock. SETUP reads all of them.
2. **`2026-09-19-signal-check.md`** — `js/core/signal-health.js` (`diagnose`), `js/core/mat-test.js`
   and `css/operator.css`. SETUP reuses all three unchanged; it adds to the stylesheet but rewrites
   nothing in it.

**Not in this plan:**

- the OPERATOR PANEL (screen 10) — undesigned, and it gets its own plan;
- any audience screen;
- SIGNAL CHECK itself, beyond the amendments already folded into its own plan on 2026-09-19.

## Decisions this plan makes

The spec leaves these open. Each is the smallest choice consistent with §4. Flag any you disagree
with before execution starts.

| # | Decision | Why |
|---|---|---|
| 1 | `savedSummary` lives in `js/core/setup-gate.js` and imports `startedCount` from `event-model.js` rather than duplicating it | Spec §4.11 puts both functions in this module. The count is already correct in the engine's code and must not fork |
| 2 | The remembered device is read and written by the **view**, not by `setupGate` | `setupGate` is pure and takes no storage. §3.8 already made the picker the owner of that key |
| 3 | The typed confirm accepts `Enter` to submit and `Esc` to cancel, and rejects anything that is not exactly the count | §4.6 asks for the number; anything looser is a ritual rather than a check |
| 4 | Pressing **Reanudar** or **Empezar evento nuevo** leaves SETUP by replacing the whole operator view, the same seam SIGNAL CHECK already uses for `S` | Spec §4.1 makes SETUP one-way. Reusing the seam means one way in and out of a full-window screen, not two |
| 5 | With **nothing saved**, `Empezar evento nuevo` still requires the full gate | §4.2's rule is about the event being new, not about whether something is being destroyed. A first event deserves a proved mat most of all |
| 6 | `canConnect` is threaded from the operator window's Web Lock claim into both `diagnose` and `setupGate` | Both need it, and deriving it twice would let them disagree about whether this window is in charge |

- [ ] **Step 1: Can "never started" be told from "started and failed"?**

driver that has started and failed is a different thing and must stay red.

before the first `start()` call** and does not become true merely because `start()` threw.

- [ ] **Step 2: If it is missing, add it**

The driver seam gains one method, on **both** drivers so the core cannot tell them apart:

```js
// js/drivers/real.js and js/drivers/mock.js — the same contract in both
// True once start() has been called and the audio graph is running. False before the first
// start(), and false again if start() rejected: "never started" and "started and failed" are
```

- [ ] **Step 5: Give the store a `clear()` beside its `archive()`**

The engine's store archives on starting fresh — *"the old log moves to a timestamped key"*. SETUP
keeps that for real events and needs the other half for rehearsals, which must not accumulate
(spec §4.6). Add to the object `createStore` returns, beside `archive`:

```js
    // Starting fresh in mock mode: a rehearsal's results can never be wanted back, and archiving
    // every one of them would grow localStorage without bound (operator spec §4.6).
    clear() {
      storage.removeItem(key);
    },
```

And its test, beside the existing archive test in `test/core/store.test.js`:

```js

// js/core/setup-gate.js
//
// SETUP's two questions as data (operator spec §4.2, §4.5): which event, and may a new one start.
// Pure — no DOM, no storage, no clock. The view supplies the diagnosis and the saved event.

import { TEST_ITEMS } from './mat-test.js';
import { startedCount } from './event-model.js';

// The links that must be good before a FRESH event may start.
//
// SEÑAL is deliberately absent. Noise is a warning with its own sentence, not a stop, and §2.1
// leaves this window no warning colour to escalate it with.
//
// PAQUETES is here even though six of six nearly implies it: the ticks reset whenever the device
// changes, so a full test proves packets flowed *recently*, not that they are flowing now. A cable
// pulled between the test and the button is exactly what this catches.
const REQUIRED_LINKS = ['mic', 'sound', 'packets'];

// `loaded` is the store's own answer (engine plan Task 14):
//   { status: 'none' } · { status: 'ok', attempts } · { status: 'corrupt' }
//
// Three results, and the third matters most. `none` and `ok`-with-no-attempts are the same thing
// to an operator and collapse to null. `corrupt` must NOT: results exist but cannot be parsed, and
// reporting that as an empty slate would invite starting fresh over an event nobody can see.
export function savedSummary(loaded) {
  if (!loaded || loaded.status === 'none') return null;
  if (loaded.status === 'corrupt') return { corrupt: true };
  if (loaded.attempts.length === 0) return null;

  const { attempts } = loaded;
  const last = attempts[attempts.length - 1];
  return {
    // startedCount reads only `.attempts`, so the log alone is a sufficient event here. The config
    // is not stored (the store's own note) and nothing on SETUP needs it.
    started: startedCount({ attempts }, null),
    attempts: attempts.length,
    lastTeamId: last.teamId,
    lastAt: last.at,
  };
}

export function setupGate({ diagnosis, test, saved, mock = false, canConnect = true }) {
  const statusOf = (key) => diagnosis.links.find((link) => link.key === key)?.status;
  const signalReady = REQUIRED_LINKS.every((key) => statusOf(key) === 'ok');

  const done = TEST_ITEMS.filter(({ key }) => test[key]).length;
  const tested = done === TEST_ITEMS.length;

  const freshEnabled = canConnect && signalReady && tested;

  const corrupt = saved?.corrupt === true;
  const resumable = saved !== null && !corrupt;

  // The reason is only ever shown under a gated button, so the enabled case has none.
  const why = !canConnect ? 'Ya hay una ventana de operador abierta'
    : freshEnabled ? null
      : !signalReady ? 'Primero hay que conectar y probar el cronómetro'
        : `Falta completar la prueba del cronómetro (${done} de ${TEST_ITEMS.length})`;

  return {
    // Not drawn at all when there is nothing to resume — not drawn and disabled. There would be
    // nothing to explain (spec §4.5).
    resume: {
      shown: resumable,
      enabled: resumable && canConnect,
    },
    fresh: {
      shown: true,
      enabled: freshEnabled,
      why,
      // A rehearsal saves under its own storage key and can never touch a real event's results
      // (engine plan decision 11), so it clears on one press. That is what keeps the typed confirm
      // rare enough to still be read when it does appear (spec §4.6).
      confirm: resumable && !mock ? 'typed' : 'none',
      count: resumable ? saved.attempts : 0,
      // Real events are archived by store.archive(now) — silent, listed nowhere. Rehearsals are
      // not, or many test events would grow localStorage for no possible benefit. A corrupt log is
      // archived either way: it is the one case where the bytes might still be recovered by hand.
      archive: corrupt || (resumable && !mock),
    },
  };
}
```

```js
  byId('su-resume').addEventListener('click', () => onResume());
  byId('su-fresh').addEventListener('click', onFreshPressed);

  // Enter presses Conectar while nothing is connected: it is the only action on the screen at that
  // point (spec §4.10). Esc does nothing here — there is nothing to cancel and nowhere to go back
  // to — except inside the typed confirm, which owns its own keys.
  document.addEventListener('keydown', onKey);

  async function connect() {
    await mat.start();
    resetMeasurement();
  }

  // The readings belong to the device that produced them, so a device change clears both the
  // packet window and the whole test (spec §3.8, §4.15).
  function resetMeasurement() {
    test = emptyTest();
    packetTimes = [];
    lastState = null;
    openedAt = performance.now();
  }

  function onMatState(state) {
    lastState = state;
    if (state.fresh && state.on) packetTimes.push(performance.now());
    packetTimes = packetTimes.filter((t) => t > performance.now() - 2_000);
    test = tickTest(test, state);
  }

  function onFreshPressed() {
    const gate = currentGate();
    if (!gate.fresh.enabled) return;
    if (gate.fresh.confirm === 'none') return onFresh({ archive: gate.fresh.archive });
    confirming = true;
    render();
    byId('su-confirm-input')?.focus();
  }

  function submitConfirm() {
    const gate = currentGate();
    const typed = byId('su-confirm-input')?.value.trim();
    if (typed !== String(gate.fresh.count)) return; // anything looser is a ritual, not a check
    confirming = false;
    onFresh({ archive: gate.fresh.archive });
  }

  function onKey(event) {
    if (confirming) {
      if (event.key === 'Enter') submitConfirm();
      if (event.key === 'Escape') closeConfirm();
      return;
    }
    if (event.key === 'Enter' && !mat.connected()) connect();
  }

  // Cancelling is also clicking anywhere else; there is no modal (spec §4.6). Clearing the dataset
  // flag is what lets renderConfirm rebuild the input next time.
  function closeConfirm() {
    confirming = false;
    byId('su-confirm').dataset.open = '';
    render();
  }

  function currentGate() {
    return setupGate({
      diagnosis: currentDiagnosis(),
      test,
      saved: savedSummary(store.load()),
      mock,
      canConnect: mat.canConnect(),
    });
  }

  function currentDiagnosis() {
    return diagnose({
      permission: mat.permission(),
      connected: mat.connected(),
      deviceLabel: mat.deviceLabel(),
      canConnect: mat.canConnect(),
      packetTimes,
      lastState,
      test,
      openedAt,
      now: performance.now(),
    });
  }

  function render() { /* Step 3 */ }

  return { onMatState, render, resetMeasurement, destroy: () => document.removeEventListener('keydown', onKey) };
}
```

```js
const el = (tag, className) => Object.assign(document.createElement(tag), { className });

// Built once and updated in place. Rebuilding innerHTML at the mat's rate — about ten times a
// second — would destroy the Conectar button's listener and any focus on every packet.
function buildChain(root) {
  const parts = new Map();
  for (const key of ['mic', 'sound', 'packets', 'signal', 'test']) {
    const li = el('li', 'sc-link');
    const dot = el('span', 'sc-link-dot');
    const label = el('span', 'sc-link-label o-label');
    const value = el('span', 'sc-link-value');
    const detail = el('span', 'sc-link-detail');
    li.append(dot, label, value, detail);
    if (key === 'mic') {
      const button = el('button', 'su-connect');
      button.id = 'su-connect';
      button.textContent = TEXT.connect;
      li.append(button);
      parts.set('connect', button);
    }
    root.append(li);
    parts.set(key, { li, dot, label, value, detail });
  }
  return parts;
}

// The class must stay `sc-link ${status}` so Task 3's `waiting` ring applies without a second rule.
// When the mat is not connected, MICRÓFONO's reading is replaced by Conectar (spec §3.8, §4.9).
function renderChain(parts, links, connected) {
  for (const link of links) {
    const p = parts.get(link.key);
    p.li.className = `sc-link ${link.status}`;
    p.dot.textContent = link.status === 'ok' ? '✓' : link.status === 'bad' ? '✕' : '';
    p.label.textContent = link.label;
    p.value.textContent = link.key === 'mic' && !connected ? '' : link.value;
    p.detail.textContent = link.detail || '';
  }
  parts.get('connect').hidden = connected;
}

const ago = (at, now) => {
  const mins = Math.round((now - at) / 60_000);
  if (mins < 1) return 'hace un momento';
  return mins < 60 ? `hace ${mins} min` : `hace ${Math.round(mins / 60)} h`;
};

function renderEvent(root, saved, { mock, teams, teamName, now }) {
  const prefix = mock ? TEXT.rehearsal : '';
  root.classList.toggle('empty', saved === null);
  root.classList.toggle('corrupt', saved?.corrupt === true);

  const [headline, detail] = saved === null
    ? [TEXT.emptyHeadline, `${prefix}${TEXT.emptyDetail}`]
    : saved.corrupt
      ? [TEXT.corruptHeadline, TEXT.corruptDetail]
      : [
        `${saved.started} de ${teams.length} universidades`,
        `${prefix}${saved.attempts} intentos registrados · la última, `
          + `${teamName(saved.lastTeamId)}, ${ago(saved.lastAt, now)}`,
      ];

  root.innerHTML = `<div class="o-label">${TEXT.eventLabel}</div>
    <div class="su-event-headline"></div><div class="su-event-detail"></div>`;
  root.querySelector('.su-event-headline').textContent = headline;
  root.querySelector('.su-event-detail').textContent = detail;
}

// Rendered only when `confirming` CHANGES. Rewriting it on every mat packet would wipe what the
// operator is halfway through typing.
function renderConfirm(root, gate, confirming) {
  root.hidden = !confirming;
  if (!confirming) { root.innerHTML = ''; return; }
  if (root.dataset.open === 'yes') return;
  root.dataset.open = 'yes';
  root.innerHTML = `<div class="su-confirm-text"></div>
    <input id="su-confirm-input" inputmode="numeric" autocomplete="off">`;
  root.querySelector('.su-confirm-text').textContent = TEXT.confirmText(gate.fresh.count);
}

function renderTest(root, test) {
  root.innerHTML = TEST_ITEMS.map(({ key, label }) =>
    `<li class="${test[key] ? 'done' : 'todo'}"><span class="sc-mark"></span><span></span></li>`).join('');
  [...root.children].forEach((li, i) => {
    const { key, label } = TEST_ITEMS[i];
    li.querySelector('.sc-mark').textContent = test[key] ? '✓' : '';
    li.lastElementChild.textContent = label;
  });
}
```
